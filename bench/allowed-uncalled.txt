# Public functions no code calls, with the reason each is allowed.
#
# One line: <path>::<function>  <reason>. The reason is mandatory. A reason naming a
# SPEC- slug must resolve, so a lane cannot be invented to silence the guard. An entry
# whose function gains a caller fails as unnecessary.
#
# See D-dead-surface-is-a-defect-class and D-the-dead-surface-allowlist-names-its-lane.

# Landed ahead of its wiring lane. Each names the spec that consumes it.
crates/rho-core/src/session/mod.rs::newest_open  SPEC-session-store-wiring: the crash offer. --continue takes newest_resumable, per D-continue-takes-the-newest-session-closed-or-not, and F-session-crash-continue stays partial until rho offers a crashed session unasked.
crates/rho-core/src/session/mod.rs::record_cancel  SPEC-session-store-wiring: it completes a half-written tool pairing on an interrupt, and no frontend has an interrupt path. rho installs no signal handler, so a Ctrl-C kills the process and the file correctly looks like a crash. F-session-cancel-without-close says the pairing repair is library-only.
crates/rho-core/src/subagent/tree.rs::spawn_child  SPEC-subagent-slots-handles-grace keeps it as the immediate queue-bypass extension point. The spec says no tool calls it, and admit_child is the queueing form the tools use.
crates/rho-core/src/usage.rs::cache_hit_ratio  SPEC-core-runtime section 1 holds the append-only-cache claim it measures, and docs/benchmarks.md reports it through the live_sessions harness. The usage summary that shows it to a user is not wired.
crates/rho-tools/src/lib.rs::builtin_registry  SPEC-core-runtime section 7 defines the registry. Production registers through builtin_registry_with_tasks_and_sandbox, which always has a task registry and a sandbox. Delete this no-tasks constructor when the rho-cli examples move to that builder.
crates/rho-plugin/src/host.rs::load_cache  SPEC-hooks-and-plugins section 5 consumes it, and F-plugin-schema-cache is planned. No frontend constructs the plugin host yet, so the whole rho-plugin surface waits on one wiring lane.
crates/rho-config/src/lib.rs::resolve_credential  No provider asks for a credential yet. The [credentials] table is documented as partly built, and item I15 wires it.
crates/rho-session-import-pi/src/lib.rs::import_pi_session  A library for an importer nobody has built a command for. It is documented as a library only.

# Test-only surface, said plainly. A review called the earlier wording an excuse, and it was:
# the only consumer in this workspace is the crate's own harness, not a third party.
crates/rho-provider-openrouter/src/lib.rs::with_base_url  Only this crate's test harness calls it, to point at a mock of OpenRouter's own path. The CLI uses with_openai_host. Delete it when the harness can use with_openai_host instead.
crates/rho-tui/src/motion.rs::sweep_frame  SPEC-tui-experience section 8 requires the renderer to write cell styles directly for zero-allocation motion, so it must not call sweep_frame. This is the allocating pure-function form the frame_bench isolated measurement and the motion unit tests use.
crates/rho-tui/src/paste.rs::units  Test-only inspection accessor. Its only callers are this crate's composer tests, which assert the paste-chip-is-one-unit invariant. Production submits through model_text, not the unit list. Delete it when those tests can assert the invariant through chip_count.

crates/rho-tui/src/paste.rs::paste  The large-paste lane above. Only rho-tui's composer and paste tests call it.

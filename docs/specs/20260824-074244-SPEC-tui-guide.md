# SPEC-tui-guide — the two minute tour, as a paged panel

Status: delivered. Driven in a pseudo-terminal; see `docs/verification/tui-guide.md`.
Owning crate: `rho-tui`. Nothing outside it changes.
Features: F-tui-guide. It completes the terminal half of F-slash-commands.

Decisions this spec implements: D-the-guide-is-a-paged-panel. It obeys
D-a-panel-nobody-can-open, and it follows the generation rule of F-generated-help.

Reviewed before implementation, as AGENTS.md step 3 requires. The review found a critical
keyboard-ownership hole, a renderer with no test, three shared edits this spec had not
admitted, and a test that could not be written against today's types. Section 8 records them.

## 1. The problem

rho promises a tour in two places and delivers none.

The slash list carries `/guide — the two minute tour`. The first frame carries
`/guide  take the two minute tour` as one of four starter hints. Typing it answers:

```
✗ error · /guide is not built yet. See F-slash-commands in docs/features.md.
```

So the first screen a new user sees invites them to run a command that fails. A
pseudo-terminal capture recorded it; see `docs/verification/tui-slash-commands.md`.

Two of the three unbuilt commands need work this spec does not cover. `/model` needs a model
registry, and `/sessions` needs a session file. `/guide` needs neither. It is the one promise
the interface can keep today.

## 2. The contract

Every signature below compiles. It was checked in a scratch crate outside the repository,
before and after the review.

### New, in `crates/rho-tui/src/guide.rs`

```rust
/// The tallest a page may be, so a short screen loses little.
pub const MAX_GUIDE_PAGE_ROWS: usize = 6;

/// One page of the guide.
pub struct GuidePage {
    /// The heading row, drawn in the heading role.
    pub title: &'static str,
    /// The body rows, never more than `MAX_GUIDE_PAGE_ROWS`.
    pub rows: Vec<String>,
}

/// The guide panel state: which page it shows.
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub struct Guide {
    /// The zero-based page index. It never exceeds the last page.
    pub page: usize,
}

/// Every page of the guide, in order, for this session.
///
/// This is the only source of the page count. Every key and command name in a page is
/// interpolated from `bindings()` and `slash_commands()`, so a rename reaches the tour.
pub fn guide_pages(model: &str, provider: &str) -> Vec<GuidePage>;

/// The footer hint while the guide is open. Pages are numbered from one.
pub fn guide_footer_hint(page: usize, pages: usize) -> String;
```

### Changed, in `crates/rho-tui/src/state.rs`

```rust
pub enum Panel {
    None,
    Approval(Approval),
    SlashList(SlashList),
    Help,
    HistorySearch(HistorySearch),
    /// The paged tour, opened by `/guide`.
    Guide(Guide),
}

impl TuiState {
    /// Route a key while the guide is open.
    fn handle_guide_key(&mut self, code: KeyCode) -> KeyAction;

    /// Open the guide at its first page.
    fn open_guide(&mut self);
}
```

`handle_chord` gains the guide in its panel guard. It reads today:

```rust
if matches!(self.panel, Panel::HistorySearch(_)) {
    return KeyAction::None;
}
```

and becomes:

```rust
if matches!(self.panel, Panel::HistorySearch(_) | Panel::Guide(_)) {
    return KeyAction::None;
}
```

### Changed, in `crates/rho-tui/src/bindings.rs`

`SlashCommand` gains one field, so the interface can tell the truth about a command in the
same way it already does about a key:

```rust
pub struct SlashCommand {
    pub name: &'static str,
    pub summary: &'static str,
    /// False means the command answers "not built yet". The list marks it, and no starter
    /// hint may name it.
    pub built: bool,
}
```

`/help`, `/quit`, and `/guide` are built. `/model` and `/sessions` are not.

### Changed, in `crates/rho-tui/src/render.rs`

`footer_hints` returns an owned hint, because the guide's hint carries a page number:

```rust
fn footer_hints(state: &TuiState, width: usize) -> Cow<'static, str>;
```

Every existing arm becomes `Cow::Borrowed`. The guide's arm is `Cow::Owned`. `footer_line`
measures the hint through `Cow`, so its width arithmetic does not change in meaning.

Three exhaustive matches gain an arm. The compiler forces each, and this spec states the
choice each one makes:

- `panel_demand` returns `(title + rows, 0)`. The guide **yields** to the transcript, as the
  help does, so a short screen truncates the page rather than squeezing the composer.
- `panel_lines` calls `guide_panel`.
- `footer_hints` returns the guide hint.

```rust
fn guide_panel(state: &TuiState, width: usize) -> Vec<StyledLine>;
```

The slash list draws `· not built yet` on an unbuilt row, from the new flag, exactly as
`help_panel` already does for a key.

### What the contract forbids

- No page reaches the model. No key routed to the guide returns an action that prompts.
- No caller outside `rho-tui` sees `Guide` or `GuidePage`. Neither is re-exported.
- `guide_pages` never returns an empty vector, so a page index always resolves.
- No page holds more than `MAX_GUIDE_PAGE_ROWS` body rows.
- No key name and no command name in a page is a literal. Prose is a literal; a name is
  interpolated.
- There is no second source for the page count. `guide_pages(..).len()` is the only one.
- No config key, environment variable, or flag changes the tour.

## 3. Behaviour rules

1. `/guide` sets `Panel::Guide(Guide { page: 0 })`. Running it again returns to page one.
2. Right arrow and space move forward one page. Left arrow moves back one page.
3. The last page does not advance. The first page does not go back. Neither is an error, and
   neither closes the panel.
4. Esc closes the panel and keeps the draft.
5. The footer reads `page 2 of 3 · ← → pages · esc close`. Pages are numbered from one.
6. **The panel owns the keyboard.** A chord returns without effect while the guide is open,
   so `ctrl-r` cannot swap the panel and `ctrl-u` cannot edit the draft behind it. A
   printable key never reaches the draft.
7. Ctrl-C keeps its meaning, because it is answered before any panel routing. It cancels a
   running turn with the guide open, and the guide stays open.
8. Every key name in a page comes from the binding table. Every command name comes from the
   slash list, and names only a built command.
9. Page one names the live model and provider.
10. A short screen truncates the page from the bottom, as it truncates the help. The page cap
    keeps the loss small. The guide never squeezes the composer.

## 4. The pages

Three pages, in this order. The prose is product copy and may be improved without a spec
change. The **structure** is the contract, and every key or command inside it is
interpolated.

1. **What rho is, and what you are talking to.** One sentence on the harness. The live model
   and provider. How to send a prompt, and how to cancel.
2. **What rho may do to your machine.** The tools it can call, that a path outside the
   session root is refused, and the two switches that narrow it: `--read-only` and
   `--sandbox`. It names where to read more.
3. **Getting around.** The keys that matter, each with the binding table's own summary: the
   command list, the help screen, history search, the external editor, and scrolling.

## 5. Test cases

Named, with the assertion each one proves. In `crates/rho-tui/tests/guide.rs` unless said
otherwise.

### Opening, paging, and closing

- `the_guide_command_opens_the_first_page` — `/guide` sets `Panel::Guide` with page zero.
  Today it pushes an error row, so this fails first.
- `the_guide_has_at_least_three_pages` — `guide_pages` returns three or more. It pins a tour
  rather than a screen.
- `right_moves_to_the_next_page` and `space_moves_to_the_next_page` — both advance, because a
  reader holds one key.
- `left_moves_to_the_previous_page` — the index falls by one.
- `right_on_the_last_page_does_not_advance` and `space_on_the_last_page_does_not_advance` —
  both boundary paths, so one cannot regress behind the other. The panel stays open.
- `the_first_page_does_not_go_back` — no underflow.
- `escape_closes_the_guide_and_keeps_the_draft` — the panel goes to `None`, the draft text
  survives.
- `reopening_the_guide_starts_at_the_first_page` — open, advance, close, open. Index zero.

### The keyboard belongs to the panel

- `a_chord_does_not_leak_through_the_guide` — with the guide open, `ctrl-r` leaves
  `Panel::Guide` in place and `ctrl-u` leaves the draft unchanged. This is the review's
  critical finding, and no other test can see it.
- `a_printable_key_does_not_reach_the_draft` — the draft is unchanged after a letter.
- `an_unknown_key_leaves_the_guide_unchanged` — the panel, the index, and the draft are all
  untouched.
- `ctrl_c_still_cancels_with_the_guide_open` — the cancel path runs and the guide stays open.

### The panel really draws

- `the_panel_draws_the_page_title_first` — the title row leads the panel, in the heading role.
- `the_first_page_draws_the_model_and_the_provider` — both strings appear, built from
  arguments and not from constants.
- `the_second_page_names_the_read_only_and_sandbox_switches` — the safety page says what it
  promises.
- `the_third_page_draws_a_key_and_its_summary` — the keys page renders rows, so the tour
  cannot ship blank.
- `a_narrow_terminal_does_not_split_a_row` — at forty columns every row fits the width, cut on
  a character boundary.
- `no_page_is_taller_than_the_page_cap` — every page respects `MAX_GUIDE_PAGE_ROWS`, so a
  short screen loses little.

### Nothing drifts

- `the_keys_page_matches_the_binding_table` — each key row on page three carries a `keys`
  value from `bindings()` **and** that binding's own `summary`. Existence alone was the weak
  test the review rejected, because a generated page can only ever hold real keys.
- `the_commands_the_guide_names_are_built` — every command name in any page resolves in
  `slash_commands()` and carries `built: true`.
- `the_footer_numbers_pages_from_one` — page index zero renders `page 1 of`, so the display is
  not zero-based.
- `the_guide_never_sends_a_prompt` — no routed key returns a prompting action, and the
  transcript gains no user row.

### The defect that prompted the work

- `a_starter_hint_names_a_built_command` — in `crates/rho-tui/tests/frames.rs`. Every
  `STARTERS` entry beginning with `/` resolves in `slash_commands()` and carries
  `built: true`. It fails today, because the first frame advertises `/guide`.
- `the_slash_list_marks_an_unbuilt_command` — the list draws `· not built yet` beside
  `/model`, so the promise is visible before a user spends a keystroke.

## 6. Out of scope

- `/model` and `/sessions`. Each needs a feature this spec does not build.
- A tour in any frontend other than the terminal.
- Configuring, translating, or theming the tour.
- A first-run trigger that opens the guide by itself. Nobody asked for it.
- Mouse navigation of the pages.
- Scrolling inside a page. The page cap replaces it, and rule 10 states the loss.
- Changing `/` or `?`. Both work today.

## 8. What the review changed

The contract went to review before any code, and it came back with four things this spec had
wrong.

**A critical keyboard hole.** `handle_chord` runs **before** the panel match in `handle_key`,
and it guards only `Panel::HistorySearch`. So with the guide open, `ctrl-r` would have swapped
the panel, and `ctrl-u`, `ctrl-k`, `ctrl-w`, and `ctrl-y` would have edited the draft behind
it. Behaviour rule 6 and `a_chord_does_not_leak_through_the_guide` close it. This is the
family `D-a-panel-nobody-can-open` exists to prevent, and the first draft walked into it.

**A renderer with no test.** The first draft named `guide_panel` and tested only state. The
tour could have shipped with blank pages and passed every test. Six render tests now cover
the panel, including a narrow terminal.

**Three shared edits the spec had not admitted.** `footer_hints` returns `&'static str`, and a
page number cannot be static, so its return type changes and every arm with it.
`panel_demand` and `panel_lines` are exhaustive matches that gain an arm, and the choice each
arm makes is now stated rather than left to the implementer.

**A test that could not be written.** `a_starter_hint_names_a_built_command` needed a `built`
flag, and `SlashCommand` had none. Adding it is a shared-struct edit, so it belongs in the
contract, and it pays twice: the slash list can now mark an unbuilt command the way the help
screen already marks an unwired key.

**One cut.** `guide_page_count` was a second source for a number `guide_pages` already owns,
and nothing forced the two to agree. It is gone.

**One narrowing, in the decision.** Ruling out static content wholesale would have made the
anti-drift test vacuous, because a fully generated page can only hold real keys. The rule is
now narrower: prose may be a literal, a key or command name may not.

# SPEC-agent-tasks — A subagent carries a task, not a prompt

Status: delivered in sprint 2, with one deliberate gap.

Owning crates:
- `rho-core` owns the task types, the gate trait, and the report extension.
- `rho-tools` owns the `spawn_agent` argument change and the sandboxed command runner.
- `rho-skills` is unchanged. It still loads the agent definition.

Features: four new rows, `F-agent-task`, `F-artifact-spec`, `F-acceptance-gate`, and
`F-unverified-child-claims`. See `docs/features.md`.

This spec extends `SPEC-subagents`. It does not replace it. It changes one tool argument
and it extends one struct and one enum. It supersedes nothing in that spec. The owner
reconciles the two files.

Every contract named here is collected in `docs/contracts-subagents.md`. That page is the
reference. This page is the reasoning.

## 1. The problem, in one sentence

A child says "done" and nobody checks it.

Today `spawn_agent` takes a bare `prompt`, and `AgentReport` returns a `summary`. A prompt
is not a task. A summary is not proof. So a lazy or confused child reports success, and the
parent trusts it. This spec makes the child carry a goal, the artifacts it must deliver, and
the checks that prove the work. rho runs the checks. The child never grades itself.

## 2. What prior art taught

**From jcode: the artifact on the edge.** jcode built agent-to-agent chat first, then
judged it a mistake. Its recorded rework is "dataflow first, chat second", and it is a
rework "by subtraction, not addition". jcode's typed handoff carries `findings`, `evidence`,
`validation`, `open_questions`, and `what_i_did_not_check`, and "the gates inspect" it. rho
takes the typed, checkable artifact and the honesty fields from jcode. rho does not take the
chat surface. See section 8 and decision D-artifact-not-chat.

**From jcode: the gate is not a script.** jcode rejected letting the agent write the flow.
An agent script puts "rigor in unvalidated agent code and the gates are bypassable". jcode
chose the server-owned, validated path instead. rho does the same. rho owns the gate, and a
child cannot skip it. See decision D-a-child-does-not-grade-itself.

**From pi: the in-process child.** pi runs a child as an in-process session and returns its
result through a plain field. There is no protocol between parent and child. rho keeps that
shape. The gate runs in the parent process after the child stops. No transport is added.

## 3. The sides, and who owns each

A side is any two places that must agree. This change has four.

| Side | What it does | Owning crate |
| --- | --- | --- |
| The parent | Builds the task and submits it. | `rho-tools`, on a `rho-core` session |
| The child | Does the work in a fresh session. | `rho-core` |
| The gate | Verifies the artifacts and the checks. | `rho-core`, run by the parent |
| The transcript | Persists the run for a human. | `rho-core`, written to disk |

The command runner is injected by `rho-tools`, so `rho-core` stays free of the sandbox.

## 4. Which contract kinds this change touches

From the list in `AGENTS.md`:

- **Public API.** `AgentTask`, the `Gate` trait, and the `ArtifactChecker` trait.
- **Data model.** `AgentTask`, `ArtifactSpec`, `Acceptance`, `GateReport`, `CheckResult`,
  `ChildClaims`, and one new `AgentOutcome` variant.
- **Error taxonomy.** New `SubagentError` variants. See section 6.
- **Persisted format.** `AgentReport` is written to the transcript, so a future rho reads it.
- **Extension surface.** A third party registers an `ArtifactChecker` for a `Named` kind.
- **Behaviour rules.** The gate runs after the child stops. A check that cannot run fails.

The configuration keys do not change.

## 5. The contract

### 5.1 The task

`AgentTask` replaces the bare `prompt`. The goal becomes the child's prompt. The artifacts
and the acceptance checks are what the gate verifies.

```rust
/// The work delegated to a child. It replaces the bare prompt.
///
/// The `goal` becomes the child's first message. The `artifacts` are the things
/// the child must deliver. The `acceptance` checks prove the work is correct.
/// rho verifies both after the child stops. The child never verifies itself.
/// See `docs/specs/20260819-102750-SPEC-agent-tasks.md`.
#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub struct AgentTask {
    /// The agent definition to run.
    pub agent: String,
    /// The goal, in the parent's words. It becomes the child's prompt.
    pub goal: String,
    /// The deliverables the child must produce. Empty is allowed.
    pub artifacts: Vec<ArtifactSpec>,
    /// The checks rho runs to prove the work. Empty is allowed.
    pub acceptance: Vec<Acceptance>,
}

impl AgentTask {
    /// A task with a goal and no checks. Defaults are stated here, not hidden.
    /// See decision D-no-four-argument-session-new.
    pub fn new(agent: impl Into<String>, goal: impl Into<String>) -> Self {
        Self {
            agent: agent.into(),
            goal: goal.into(),
            artifacts: Vec::new(),
            acceptance: Vec::new(),
        }
    }

    /// Add the deliverables the child must produce.
    pub fn with_artifacts(mut self, artifacts: Vec<ArtifactSpec>) -> Self {
        self.artifacts = artifacts;
        self
    }

    /// Add the checks rho runs to prove the work.
    pub fn with_acceptance(mut self, acceptance: Vec<Acceptance>) -> Self {
        self.acceptance = acceptance;
        self
    }

    /// Reject a task rho cannot verify. A goal is required.
    pub fn validate(&self) -> Result<(), SubagentError> {
        if self.goal.trim().is_empty() {
            return Err(SubagentError::EmptyGoal);
        }
        Ok(())
    }
}
```

### 5.2 What the child must deliver

`ArtifactSpec` says what the child must deliver, in a form rho can check without asking the
child. It is an enum, so a new built-in kind arrives as a new variant. A third-party kind
arrives through the `Named` variant and a registered checker, so it never edits this enum.

```rust
/// One thing the child must deliver, in a form rho can check.
///
/// `File` and `Command` are the built-in kinds. `Named` routes to a registered
/// `ArtifactChecker`, so a third party adds a kind without editing this enum.
#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
#[serde(tag = "kind", rename_all = "snake_case")]
pub enum ArtifactSpec {
    /// A file that must exist and be non-empty, under the session root.
    File { path: PathBuf },
    /// A command that must exit zero. It runs under the parent's sandbox.
    Command { run: String },
    /// A named artifact kind resolved by a registered `ArtifactChecker`.
    ///
    /// The field is `name`, not `kind`. `kind` is the serde tag for this enum, and
    /// serde refuses a variant field that collides with its tag. The first draft
    /// said `kind` and did not compile. AGENTS.md step 3 says to paste a signature
    /// into a scratch crate, and this is why.
    Named { name: String, value: String },
}
```

### 5.3 The acceptance check

`Acceptance` is one named check rho runs. rho's gate runs it, in the parent process, after
the child stops and before the report returns to the model. The child does not run it.

```rust
/// One named acceptance check. rho runs it, never the child.
///
/// The `label` names the check in the report and in an error. The `check` is the
/// thing that must hold. It reuses `ArtifactSpec`, so the surface stays small.
#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub struct Acceptance {
    /// A short label, for the report and for a refusal.
    pub label: String,
    /// The condition the gate verifies.
    pub check: ArtifactSpec,
}
```

### 5.4 The gate, and its extension point

The gate is a trait, so a caller can add a check kind without editing rho. rho ships one
default gate. The extension point is `ArtifactChecker`. A third party registers a checker
for a `Named` kind. The default gate dispatches every `Named` artifact to the checker whose
`kind()` matches. An unmatched kind is refused with a named error, never skipped.

```rust
/// Verifies a task after the child stops. rho owns the gate. The child never
/// runs it, so a child cannot certify its own work. See decision
/// D-a-child-does-not-grade-itself.
#[async_trait]
pub trait Gate: Send + Sync {
    /// Check every artifact and every acceptance check. Return one verdict per
    /// item, in declaration order. rho runs this in the parent process, after
    /// the child stops and before the report returns to the model.
    async fn verify(&self, task: &AgentTask, ctx: &GateContext) -> Result<GateReport, SubagentError>;
}

/// Resolves one `Named` artifact kind. A third party registers an impl to add a
/// check kind, without editing rho. This is the extension point.
#[async_trait]
pub trait ArtifactChecker: Send + Sync {
    /// The `Named` kind this checker handles.
    fn kind(&self) -> &str;
    /// Inspect one named artifact and return a verified verdict.
    async fn check(&self, value: &str, ctx: &GateContext) -> CheckOutcome;
}

/// What the gate needs to run. `rho-tools` supplies the sandboxed command
/// runner, so `rho-core` stays free of the sandbox.
pub struct GateContext {
    /// The session root. A file artifact must resolve under it.
    pub session_root: PathBuf,
    /// Cancels a long command check with the parent.
    pub cancel: CancelToken,
    /// Runs a `Command` artifact under the parent's sandbox.
    pub runner: Arc<dyn CommandRunner>,
}

/// Runs a command check under the parent's sandbox. `rho-tools` supplies it.
#[async_trait]
pub trait CommandRunner: Send + Sync {
    /// Run a command under `root` and return its exit code.
    async fn run(&self, command: &str, root: &Path, cancel: &CancelToken) -> std::io::Result<i32>;
}

/// The verdict of one check. Only the gate builds one. The child cannot.
#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub enum CheckOutcome {
    Pass,
    Fail { detail: String },
}
```

### 5.5 The report extension

The existing `AgentReport` gains two fields. `gate` is rho's verified verdict. `claims` is
the child's own, unverified report. They are separate fields on purpose. That separation is
the whole point. A reader must never mistake a claim for a verified result.

```rust
/// What a child returns to its parent. Unchanged fields are omitted here for
/// brevity; see `crates/rho-core/src/subagent.rs`.
#[derive(Clone, Debug, PartialEq, Serialize, Deserialize)]
pub struct AgentReport {
    pub agent: String,
    pub outcome: AgentOutcome,
    pub summary: String,
    pub usage: Usage,
    pub turns: u32,
    pub transcript: Option<PathBuf>,

    // --- Added by SPEC-agent-tasks ---
    /// rho's verified verdict on the task. Empty when the task declared no
    /// checks. This is the truth, not the child's claim. A missing field in an
    /// old transcript reads as an empty, all-passed report.
    #[serde(default)]
    pub gate: GateReport,
    /// The child's own, unverified claims. Never a substitute for `gate`.
    #[serde(default)]
    pub claims: ChildClaims,
}

/// The gate's verified verdict. One result per declared item, in order.
#[derive(Clone, Debug, Default, PartialEq, Eq, Serialize, Deserialize)]
pub struct GateReport {
    pub artifacts: Vec<CheckResult>,
    pub acceptance: Vec<CheckResult>,
}

impl GateReport {
    /// True only when every check passed. An empty report passes.
    pub fn passed(&self) -> bool {
        self.artifacts.iter().all(|r| r.passed) && self.acceptance.iter().all(|r| r.passed)
    }
}

/// One verified verdict. Only the gate builds this. See section 6.
#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub struct CheckResult {
    pub label: String,
    pub passed: bool,
    /// Why it passed or failed. For a human and for the model.
    pub detail: String,
}

/// The child's own words. **Unverified.** The gate never reads these. They are
/// jcode's honesty fields. They catch a lazy child cheaply. They are not proof.
#[derive(Clone, Debug, Default, PartialEq, Eq, Serialize, Deserialize)]
pub struct ChildClaims {
    /// Questions the child could not resolve. Unverified.
    pub open_questions: Vec<String>,
    /// Things the child says it did not check. Unverified.
    pub what_i_did_not_check: Vec<String>,
}
```

`AgentOutcome` gains one variant. When the child claims done but the gate fails a check, the
outcome must not be `Done`. The new variant carries the failed labels.

```rust
#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum AgentOutcome {
    Done,
    OutOfTurns,
    Canceled,
    Failed { reason: String },
    /// The child stopped, but the gate failed one or more checks. It holds the
    /// failed labels. It is never `Done`, so a reader that trusts the outcome
    /// still sees a failure. Added by SPEC-agent-tasks.
    Rejected { failed: Vec<String> },
}
```

## 6. What the contract forbids

Each forbidden case has a name.

- **`SubagentError::EmptyGoal`.** A task with an empty goal is refused. rho cannot delegate
  nothing.
- **`SubagentError::UnknownArtifactKind { kind }`.** A `Named` artifact whose kind has no
  registered checker is refused. It is never skipped. A skipped check is a fail-open hole.
- **`SubagentError::ArtifactPathEscapesRoot { path }`.** A `File` artifact that resolves
  outside the session root is refused. The root is a security boundary.
- **A check that cannot run fails.** A command that cannot start, or a timeout, yields
  `CheckOutcome::Fail`, never a pass. The gate fails closed. See decision D-todo-in-a-green-stage.
- **The no-self-grade invariant.** No type gives the child a way to set `passed`. The child
  fills `ChildClaims` only. The gate alone builds a `CheckResult`. A child cannot forge a
  pass, because the field does not exist on its side. See decision D-a-child-does-not-grade-itself.

```rust
pub enum SubagentError {
    // ... existing variants ...
    #[error("a task must state a goal. An empty goal cannot be delegated.")]
    EmptyGoal,
    #[error(
        "no checker is registered for the artifact kind \"{kind}\". \
         Register an ArtifactChecker for it, or use a built-in kind."
    )]
    UnknownArtifactKind { kind: String },
    #[error(
        "the artifact path \"{path}\" is outside the session root. \
         A file artifact must resolve under the root."
    )]
    ArtifactPathEscapesRoot { path: String },
}
```

## 7. What an old reader does with a new field

The `AgentReport` is written to the transcript, so a future rho reads it. A silent drop is a
defect. So the rules are explicit.

- **A new reader reads an old transcript.** The `gate` and `claims` fields are missing.
  `#[serde(default)]` fills them. `gate` reads as an empty, all-passed report. `claims` reads
  as empty. This is safe, because an old transcript predates the gate.
- **An old reader reads a new transcript.** Extra fields are dropped by serde. This is the
  one real risk. An old reader that trusts `summary` alone would miss the gate verdict. So
  the verdict is also carried in `outcome`. A rejected task is `AgentOutcome::Rejected`, not
  `Done`.
- **An old reader meets `AgentOutcome::Rejected`.** It cannot parse the new variant, so the
  read fails. This is deliberate. `AgentOutcome` has no `#[serde(other)]` catch-all. A
  catch-all would map a rejected task to a known variant, and that is the fail-open bug this
  repository shipped twice. See decisions D-plugin-does-not-classify-itself and
  D-mcp-does-not-classify-itself. A failed read is safe. A rejected task read as done is not.
- **In this repository, all readers rebuild together.** The report crosses no process
  boundary to an independently-versioned reader in this spec. The transcript is for a human.

## 8. This spec adds no messaging, no DAG, and no scheduler

This spec adds a typed artifact. It does not add a way for one agent to message another. It
adds no dependency graph. It adds no scheduler.

jcode's reason is recorded. Agent-to-agent chat is "the wrong shape" for dataflow. The real
transfer is "node -> dependent via the artifact on the edge". jcode reworked its design "by
subtraction, not addition", and cut the direct-message, broadcast, topic-channel, and
shared-key-value surfaces as primary mechanisms. See decision D-artifact-not-chat.

A dependent's input will one day come from an upstream artifact, when that artifact arrives.
This spec only prepares for it. The `ArtifactSpec` is the typed unit that a future edge will
carry. This spec defines that unit. It does not define the edge, the scheduler, or the
hydration. Those are a later spec.

## 9. Out of scope

- The dependency edge, the scheduler, and input hydration from an upstream artifact.
- Any agent-to-agent message, broadcast, channel, or shared key-value store.
- A workflow preset that chains tasks. It needs the command layer, `F-slash-commands`.
- A cost prediction before a check runs. The budget governor still acts one turn late.
- A read-only spawn tool. `spawn_agent` stays `ToolKind::Execute`. See `SPEC-subagents`.
- Any change to the four subagent limits, the policy composition, or the tool intersection.
- **`Acceptance` and the `Named` artifact kind have no CLI path.** A Rust caller reaches
  them. A model cannot. `spawn_agent` accepts `artifacts` as a list of file names only.
  A command string is not accepted. See decision `D-an-acceptance-check-has-a-trusted-author`.

## 8a. What the implementation added

The implementation is in `crates/rho-core/src/agent_task.rs`, and the tests are in
`crates/rho-core/tests/agent_task.rs`. Three things arrived that this spec did not state.

**A file artifact goes through `confine`.** An artifact path is attacker-influenced whenever a
definition or a model writes it. So it obeys the same boundary as every tool, and a path
outside the session root fails. Without it a task could assert a file the child never wrote.
`a_file_artifact_outside_the_session_root_fails` pins it.

**`CheckResult::from_outcome` is crate-internal.** No public constructor takes a `passed`
flag, so nothing outside `rho-core` can build a passing verdict. The no-self-grade rule is a
type property, not a runtime check.

**The gate does not run inside `collect_report`.** A gate needs a sandboxed command runner,
and `rho-core` must hold no sandbox. So `collect_report` leaves `gate` empty and a caller
merges the verdict. That keeps the crate boundary in `AGENTS.md` intact.

- **A check that a definition supplies.** An agent definition cannot declare an acceptance
  check yet, so `an_untrusted_project_definition_supplies_no_check` describes behaviour that
  does not exist. It belongs with the definition-level path, not here.
- **A check the parent selects by label.** `a_parent_may_select_a_check_by_label_only` needs a
  declared set of labelled checks for the model to choose from. That set arrives with the
  definition-level path too.

## 9a. One open question, recorded rather than hidden

`ArtifactSpec::Command` requires exit zero. An `Acceptance` that wraps a `Command` does the
same thing. So the two lists overlap, and a smaller design is one list where `artifacts` is
sugar over `acceptance`.

This spec keeps two lists, for one reason. A missing deliverable and a failing check are
different failures, and the parent model acts differently on each. "You did not write the
file" and "the test failed" need different next steps.

**The cost is a larger contract, and AGENTS.md prefers the smaller one.** So the question
stays open until the first implementation. If the gate ends up with one code path for both
lists, collapse them and write the decision. Do not discover this after a caller depends on
both field names.

## 10. Test cases

Every test uses a scripted fake provider. Every test isolates the filesystem with
`tempfile`. No test uses the network. No test uses `sleep`.

The gate, in `rho-core`:
- `a_missing_file_artifact_fails_the_task` — a declared file that does not exist yields a
  failed check.
- `an_empty_file_artifact_fails_the_task` — a declared file that exists but is empty fails.
- `a_present_file_artifact_passes` — a declared file that exists and is non-empty passes.
- `a_command_that_exits_zero_passes` — a command acceptance check that exits zero passes.
- `a_failing_acceptance_check_fails_the_task` — a command that exits non-zero fails the task.
- `a_command_that_cannot_start_fails_closed` — an unrunnable command fails, never passes.
- `a_task_with_no_artifacts_still_runs` — an empty task passes the gate and reports done.

The no-self-grade rule, in `rho-core`:
- `a_child_that_skips_its_declared_artifact_is_rejected` — the outcome is `Rejected`,
  not `Done`, when a declared artifact is absent.
- `the_gate_result_and_the_child_claim_are_separate_fields` — `gate` holds the verdict, and
  `claims` holds the child's words, and neither writes the other.
- `a_child_cannot_mark_its_own_acceptance_as_passed` — the child's report cannot flip a gate
  verdict, because no type gives the child a `passed` field.
- `a_child_cannot_mark_its_own_acceptance_as_passed` — the reported outcome follows the
  gate, not the child.
- `a_file_artifact_outside_the_session_root_fails` — an artifact path obeys `confine`.
- `a_task_with_no_goal_is_refused` — a task rho cannot act on is refused, and the refusal
  teaches.
- `a_registered_checker_handles_its_named_kind` — the extension point works with no edit to rho.
- `an_unknown_artifact_kind_fails_closed_rather_than_skipping` — the fail-open shape is refused.
- `an_old_record_without_a_gate_field_reads_as_an_empty_report` — the persisted format still
  loads, and it claims no pass it did not earn.

The trusted-author rule. See decision D-an-acceptance-check-has-a-trusted-author.

**This list was wrong, and the correction is recorded rather than quietly patched.** It named
four tests that did not exist, so the spec claimed proof it did not have. `bench/check-ids.py`
cannot catch that, because a test name is not an id. Two of the four are now real tests. Two
described behaviour that is not built, so they moved to `## 9. Out of scope`.

Proven now:
- `the_model_cannot_declare_a_command_check` — in `rho-tools`. The tool arguments hold file
  names only, so nothing the model writes can become a command the gate runs. This is the
  test the missing `the_model_cannot_declare_a_command_check` was reaching for, under the
  name it really has.
- `a_gate_command_obeys_the_parent_sandbox` — in `rho-tools`, in `tests/sandbox.rs`. A
  confined runner writes inside the session root and fails outside it. It skips when the host
  has no sandbox backend, the same way every other sandbox test does.
- `a_cancelled_gate_command_stops` — a gate check stops with its parent, so a cancelled run
  leaves no test suite running.

The error taxonomy, in `rho-core`:
- `an_unknown_artifact_kind_fails_closed_rather_than_skipping` — a `Named` kind with no checker
  yields `UnknownArtifactKind`.
- `a_task_with_no_goal_is_refused` — `AgentTask::validate` yields `EmptyGoal`.
- `a_file_artifact_outside_the_session_root_fails` — a path outside the root yields
  `ArtifactPathEscapesRoot`.

The extension point, in `rho-core`:
- `a_registered_checker_handles_its_named_kind` — a custom `ArtifactChecker` handles its
  kind without editing the enum.

The serde rules, in `rho-core`:
- `an_old_record_without_a_gate_field_reads_as_an_empty_report` — a report with no `gate` field reads
  as all-passed and empty.
- `a_rejected_outcome_round_trips` — `AgentOutcome::Rejected` serializes and deserializes.

The tool, in `rho-tools`:
- `a_child_that_skips_its_declared_artifact_is_rejected` — the outcome is `Rejected`, not
  `Done`, when a declared file is absent.
- `a_child_that_delivers_its_artifact_passes_the_gate` — a present, non-empty file passes.
- `a_task_with_no_declared_artifact_behaves_as_before` — an empty artifacts list is allowed.
- `the_model_cannot_declare_a_command_check` — the schema accepts file names only. A command
  string is refused. See decision `D-an-acceptance-check-has-a-trusted-author`.
- `spawn_agent_reports_a_rejected_task_as_an_error_result` — a failed gate returns an error
  tool result, so the model can choose again, and the parent continues.
- `spawn_agent_without_a_goal_is_a_result_not_a_fault` — a missing goal returns an error tool
  result, not a panic.

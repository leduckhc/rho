# D-vim-mode-waits — No vim mode until a user asks twice

**Question (owner):** Claude Code ships a vim mode. Does rho?

**Decision:** Not now. The composer gets readline keys only: the arrows, `ctrl-a`, `ctrl-e`,
`ctrl-k`, `ctrl-u`, `ctrl-w`, `ctrl-y`, `alt-b`, and `alt-f`. A modal editor waits for a
stated need from a user who runs rho.

**Reason:** A modal editor doubles the input state machine. Every panel, every chip, and
every key hint then needs a second answer. The readline set covers the same edits with no
mode at all, and a shell user already knows it.

The single key `v` starts a transcript selection, which is the one vim habit this spec keeps.
It costs no mode in the composer, because a selection is its own mode.

**Rules out:** A `tui-vim` config key in this spec. A normal and insert split in the
composer. Any binding that only makes sense beside a modal editor.
